# Restart file fixtures

`sukinda10.rst` is a real CrunchTope restart, not a synthetic one. Every shape ambiguity the
regridder has to resolve was settled by matching against tecplot output rather than by reasoning,
so a genuine file is load-bearing here.

Generated by running `sukinda_column.in` — the `tests/omphalos_test` deck with a `save_restart`
line added — under the CrunchTope build that `omphalos/settings.py` points at, `BOGLSource2026`.
10 cells, 23 primary / 17 secondary species, 5 output times, about three seconds:

```
cp tests/omphalos_test/{sukinda_column.in,SukindaCr53.dbs,aqueous.dbs,CatabolicPathways.in} .
# add 'save_restart  sukinda10.rst' to the RUNTIME block
CrunchTope sukinda_column.in
```

The restart is written at the *end* of the run, so it corresponds to output **5**, not output 1 —
`porosity5.tec`, `totcon5.tec` and `conc5.tec` are the reference profiles, and
`verify_reference(..., file_num=5)` is what pairs them up.

`stage1.in` is the same deck on 25 cells restarting from a regridded file, kept as the worked
example of a two-stage chain that changes resolution. It runs to completion against a
`sukinda25.rst` produced by

```
python -m omphalos.restart_file regrid sukinda10.rst --nx-in 10 --nx-out 25 \
    -o sukinda25.rst --input sukinda_column.in
```

The databases are not duplicated here; they live in `tests/omphalos_test/`.

## Build sensitivity

The same deck was run under both local CrunchTope builds, `BOGLSource2026` and `JennySource2025`.
They produce files of identical length with identical record counts and identical inferred shapes,
agreeing on every reference check to the same figure; 617 of 125404 bytes differ, which is
compilation round-off in the state arrays plus a different `dtold`. The tests pass against either,
so the fixture is not tied to one build.

One thing both binaries agree on and both source trees contradict: `spold` is written as
`(ncomp+nspec, 0:nx+1)`, while `GlobalArrayAllocation.F90` in both trees declares
`(ncomp+nspec, nx, ny, nz)`. That is why `omphalos/restart_file.py` solves each record's x extent
from its element count rather than asserting the declared one, and reports the mismatch instead of
absorbing it.
